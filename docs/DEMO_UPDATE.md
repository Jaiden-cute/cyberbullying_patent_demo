# 学校心理咨询中心演示程序修改说明

首页面向学校心理咨询中心工作人员。左侧选聊天材料和受影响学生，结果区先显示「发生了什么」，随后显示「为什么值得关注」和「接下来怎么跟进」。评分、采用的支持策略、与学生沟通时可参考的话放在同一个折叠区，聊天原文可单独查看。

视觉更新采用深蓝侧栏、浅色工作区和独立内容卡片。风险等级保留完整文字，并用颜色区分。窄屏按阅读顺序纵向排列依据和跟进动作。主题与样式分别保存在 `.streamlit/config.toml` 和 `assets/workspace.css`。[Streamlit 主题与组件样式建议](https://docs.streamlit.io/develop/concepts/design/best-practices) · [GOV.UK 版式指南](https://design-system.service.gov.uk/styles/layout/)

| 界面内容 | 与专利流程的对应关系 |
| --- | --- |
| 事件概况 | 按权利要求 1、4、5 展示整理出的受影响学生、时间、发起者、事件类型和一条原话。 |
| 回应筛选与重点参考的回应 | 对应权利要求 1、6–8。第 1 次展示两条纳入的回应、一条被排除的数学作业消息和程序选出的主要回应，并结合事发情境提示表达线索。 |
| 过往事件与跨事件比较 | 对应权利要求 1、9。分别显示同一学生近期事件次数和实际完成的回应比较，第 3 次能看到从已保存记录读回两次回应及日期。 |
| 分级支持与安全优先 | 对应权利要求 10。第 4 次展示「较高风险」及工作人员的具体行动，严重威胁案例显示人工复核提示和实际触发的安全信号。 |
| 历史与跟进 | 对应具体实施方式的第七步。筛选学生、回看事件与建议，填写并重新读取已采取的措施和下一步安排。 |

演示走权利要求 1 的文本流程，复用原有公式、分级阈值、策略和历史写入流程。第 4 次的结果依赖此前的事件历史，录屏应从同一个新数据库按顺序完成五次提交。[逐镜头录制步骤](DEMO_SCRIPT.md)

## 实际验证

从空数据库依次运行五个虚构场景，支持级别依次为重点关注、一般关注、重点关注、较高风险、高风险。浏览器实跑前三次，确认第三次在页面上显示了从数据库读取的两次历史回应和日期。跟进记录经界面保存后，用新会话打开第三次事件仍能读到。[规则演示实测](../reports/user_demo_validation.json)

在另一个空数据库里，从首页连续运行前三个场景。三次均使用 Sentence-BERT、标记为 `synthetic_training_demo` 的已训练分类器和本机 Qwen2.5-7B，界面回复均显示「AI 生成」。第三次实际比较了前两条历史回应，两条历史的掩饰程度都低于计入重复模式的门槛，重复程度计算结果为零。本机三次分析分别耗时约 42、66 和 43 秒。早一轮试跑中，第二次生成超时，界面显示了「预设支持回复」。[连续三次模型实测](../reports/user_demo_ai_history.json)

全量回归测试共 **72 项通过**，包含界面、历史持久化、公式和已训练模型的测试。运行命令如下。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
```
